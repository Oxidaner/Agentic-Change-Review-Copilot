# Local Development

## Current Reality

The repository now starts on the new testflow API surface, and task detail responses include derived workflow, execution-plan, and trace-event views.

Default endpoints:
- `POST /api/v1/test-tasks`
- `GET /api/v1/test-tasks/{task_id}`
- `GET /api/v1/test-tasks/{task_id}/timeline`
- `POST /api/v1/test-tasks/{task_id}/retry`
- `GET /api/v1/test-tasks/{task_id}/report`
- `GET /api/v1/test-metrics`
- `POST /api/v1/webhooks/github/pull-request`

The old `internal/review` package still exists in-tree as legacy code, but it is not the active entrypoint anymore.

## Start With Docker Compose

```bash
docker compose up --build
```

The API will be available at `http://localhost:8080`.

## Key Environment Variables

- `PORT`: HTTP listen port, defaults to `8080`
- `DATABASE_URL`: when set, the API uses PostgreSQL instead of the in-memory store
- `AUTO_MIGRATE=1`: runs the SQL files under `migrations/` on startup
- `GITHUB_WEBHOOK_SECRET`: when set, the GitHub PR webhook endpoint requires a valid `X-Hub-Signature-256` HMAC signature

## PostgreSQL Integration Tests

When a local PostgreSQL instance is available, run the `testflow` lifecycle integration tests with:

```powershell
$env:TEST_DATABASE_URL = "postgres://review:review@localhost:5432/review_copilot?sslmode=disable"
go test ./internal/testflow -run Postgres -count=1
```

The same PostgreSQL integration path now also runs in GitHub Actions via `.github/workflows/ci.yml`.

## GitHub Webhook Adapter

A narrow GitHub PR webhook adapter is now available at `POST /api/v1/webhooks/github/pull-request`.

Supported actions:
- `opened`
- `reopened`
- `synchronize`
- `ready_for_review`

Unsupported PR actions are accepted but intentionally ignored, which keeps upstream webhook delivery simple while avoiding unnecessary task creation.

If `GITHUB_WEBHOOK_SECRET` is configured, webhook requests must also include a valid `X-Hub-Signature-256` header generated by GitHub for the raw request body.

Minimal example:

```json
{
  "action": "synchronize",
  "number": 42,
  "repository": {
    "name": "gateway-service",
    "full_name": "octo/gateway-service"
  },
  "pull_request": {
    "number": 42,
    "title": "adjust auth routing",
    "head": {
      "ref": "feature/auth-routing",
      "sha": "def456"
    },
    "base": {
      "ref": "main",
      "sha": "abc123"
    }
  }
}
```

## CLI Adapter

The repository now includes a local CLI under `cmd/testflow-cli/` for driving the HTTP API without writing raw `curl` commands.

Examples:

```bash
go run ./cmd/testflow-cli create -file request.json
go run ./cmd/testflow-cli create -file request.json -wait
go run ./cmd/testflow-cli get -task-id tsk_123
go run ./cmd/testflow-cli report -task-id tsk_123 -format json
```

Default target:
- `http://localhost:8080`

Override options:
- `-base-url`
- `TESTFLOW_API_BASE_URL`

## Optional Live HTTP Probe Mode

When you want real HTTP execution instead of heuristic execution, include this in `payload.metadata`:

Supported keys:
- `api_base_url`
- `variables`
- `default_headers`
- `requests[].headers`
- `requests[].cookies`
- `requests[].query`
- `requests[].body`
- `requests[].timeout_ms`
- `requests[].max_duration_ms`
- `requests[].max_attempts`
- `requests[].expect_status`
- `requests[].expect_headers`
- `requests[].expect_headers_absent`
- `requests[].expect_cookies`
- `requests[].expect_cookies_absent`
- `requests[].expect_body_contains`
- `requests[].expect_body_not_contains`
- `requests[].expect_json_present`
- `requests[].expect_json_absent`
- `requests[].expect_json`
- `requests[].expect_json_types`
- `requests[].extract`
- `requests[].extract_headers`
- `requests[].extract_cookies`

```json
{
  "api_base_url": "http://localhost:8080",
  "variables": {
    "username": "alice"
  },
  "default_cookies": {
    "locale": "en-US"
  },
  "requests": [
    {
      "name": "login",
      "method": "POST",
      "path": "/login",
      "headers": {
        "Content-Type": "application/json"
      },
      "cookies": {
        "flow": "login"
      },
      "body": {
        "user": "{{username}}"
      },
      "timeout_ms": 2000,
      "max_duration_ms": 250,
      "max_attempts": 2,
      "expect_status": 200,
      "expect_headers": {
        "Content-Type": "application/json"
      },
      "expect_json_present": ["token"],
      "expect_json": {
        "token": "abc123"
      },
      "expect_json_types": {
        "token": "string"
      },
      "extract": {
        "auth_token": "token"
      },
      "extract_headers": {
        "request_id": "X-Request-Id"
      },
      "expect_cookies": {
        "session_id": "abc123"
      },
      "extract_cookies": {
        "session_cookie": "session_id"
      }
    },
    {
      "name": "profile",
      "method": "GET",
      "path": "/profile",
      "timeout_ms": 2000,
      "max_duration_ms": 250,
      "headers": {
        "Authorization": "Bearer {{auth_token}}",
        "X-Session-Mirror": "{{session_cookie}}"
      },
      "query": {
        "trace_id": "{{request_id}}"
      },
      "expect_status": 200,
      "expect_headers_absent": ["X-Debug-Trace"],
      "expect_body_contains": ["admin"],
      "expect_body_not_contains": ["stacktrace"],
      "expect_json_present": ["user.id"],
      "expect_json_absent": ["debug.trace"],
      "expect_json": {
        "status": "ok",
        "user.role": "admin"
      }
    }
  ]
}
```

Requests run in order, and values extracted from one response body, response header, or response cookie can be injected into later headers, query parameters, paths, bodies, or cookies. Successful responses also seed a simple in-memory session cookie store for later requests in the same workflow. Each request can also declare its own hard timeout budget, soft latency budget, and retry count. Live execution artifacts now preserve request, response, assertion, cookie/session, retry, timeout, and extraction evidence with basic redaction for sensitive keys.
